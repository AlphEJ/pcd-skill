# PCD 概念说明

> 本文件是 PCD 双版本范式的完整概念说明。用户问"PCD 是什么 / 为什么有用 / 为什么双版本 / 和 PRD 什么关系 / 连接规则怎么用 / 为什么写前要先检验命题"时读取，用于向用户解释。

## 什么是 PCD

- 英文缩写：PCD
- 英文全称：Personal-Cognition-Document
- 中文全称：个人认知文档
- 旧称：PPD（Personal-Principle-Document，个人原则文档）

**更名说明**：本范式最初命名为"个人原则文档（PPD）"。使用中发现文档内容以认知推导与思考链条沉淀为主（思考缘起、概念释义、推导链、可解释场景、关联思考），"原则"一词难以完全概括，故更名为"个人认知文档（PCD）"。"认知"是上位概念——原则本身是从认知推导出来的产物，PCD 同时涵盖思考过程与推导出的原则。旧称 PPD 保留，用于兼容历史文档与检索。

**重要备注**：PCD 是个人知识库自定义范式，并非学术界/工业界通用标准。它参考了产品 PRD 的工程化思维——把模糊的想法变成结构化、有边界、可落地的规格说明——把个人思考做工程化沉淀：将隐性的个人思考显性化，沉淀为可迭代、可关联的认知资产；支持 AI Skill 自动生成、Obsidian 双向链接。对外介绍务必注明非行业标准。

## 和 PRD 的关系

PCD 参考 PRD 的只是**结构化方法论**：把脑子里的模糊想法，拆解成有边界、可回溯、可迭代的规格说明。两者的处理对象、核心目标、模块结构完全不同——PCD 的模块是**自己的、适配个人认知沉淀的专属结构**，不逐一对标 PRD 的某个节点。

**PRD（Product-Requirements-Document，产品需求文档）**

- 面向：软件产品、功能
- 作用：把脑子里模糊的产品想法，变成一套结构化、有边界、可落地的规格说明，对齐团队，指导开发。
- 关注点：产品要做什么、为什么做、边界是什么、异常情况如何处理。

**PCD（Personal-Cognition-Document，个人认知文档）**

- 面向：个人深度感悟、人生命题、认知思考、人性观察
- 作用：把脑子里零散、口语化的感悟，整理成一套严谨、可回溯、可迭代升级的思想说明书。
- 关注点：这个观点从何而来、概念如何定义、推导逻辑是什么、这条道理本身是否成立、哪些场景不能用这个道理、可以解释哪些现实现象、和哪些已有认知文档相关。

### 核心对比

| 项目 | PRD 产品需求文档 | PCD 个人认知文档 |
| --- | --- | --- |
| 处理对象 | 软件产品、业务功能需求 | 个人深度感悟、人生命题、人性与成长观察 |
| 输入来源 | 业务想法、用户反馈 | 碎片化感悟、社会现象观察、视频/文章/对话素材 |
| 核心目标 | 消除团队成员之间的需求歧义，指导开发落地 | 消除「未来的自己」对当下思考的理解歧义；把隐性认知显性化，打造可迭代的个人认知资产 |
| 重点模块 | 业务背景、需求详述、异常分支、非目标、验收标准、版本记录 | 思考缘起、概念释义、完整推导链、边界约束、版本变更日志、跨文档关联 |

## 双版本体系（结构版 + 叙事版）

PCD 把同一条认知写成两份文档，分别服务两类读者：

| | 结构版 | 叙事版 |
| --- | --- | --- |
| 本质 | 认知数据库 = 叙事版的 PRD | 认知文章 |
| 读者 | AI（解析/检索/关联/迭代）+ 未来的自己（核对） | 当下的自己与他人（阅读/记忆/分享） |
| 形态 | YAML 元信息 + 10 个结构化模块 | 8 要素连贯文章 + 核心记忆卡 |
| 追求 | 可检索、可核对、可迭代、零歧义 | 可读、可记忆、可复述 |
| 版本 | 独立版本号，随认知迭代 | 不设独立版本号，跟随结构版同步 |

**双版本联动**：结构版认知更新（升版本）→ 叙事版标「待同步」→ 按变更点同步 → 标「已同步」。

**命名规则**：两份文档共享同一主题文件名，靠后缀配对——`主题名-PCD-结构版.md` / `主题名-PCD-叙事版.md`。**文件名管配对，标题管内容**：文件名只负责让两份文档成对相邻；文档内部标题保持各自职责。

**为什么需要两个版本（人机分工的最优解）**：人负责判断、悟道、提炼核心观点、提供一手经验；AI 负责记忆存储、表达优化、网络关联、自动生成叙事版。结构版保证 AI 能读懂、能关联，叙事版保证人能记住、能复述。

## 范式核心价值

1. **隐性认知显性化**：不再只留存一句金句，完整保存整套思考逻辑链，防止时间流逝之后只记得结论，遗忘思考过程。
2. **版本日志记录思想演化**：大多数人的感悟，认知迭代后直接删除旧内容；版本日志完整记录自己思想变化，本身就是元认知训练。
3. **边界约束规避道理滥用**：绝大多数人生观点翻车，根源就是没有写清"什么情况不能用"，边界约束专门解决该问题。
4. **认知网络构建**：通过 `related_principles` 字段关联其他 PCD 文档，各个独立的思考文档编织成一张互相引用的认知网络，而不是孤立碎片。
5. **面向 AI Agent 友好**：固定结构化模板，可以交给 Skill 自动解析、生成、校验一致性；相当于给自己认知系统设计一套 API。
6. **可读性不缺席（叙事版 + 记忆卡）**：叙事版保证能像文章一样通读；核心记忆卡解决"读完就忘"——人靠关键词串联记忆（大脑是网络不是硬盘、语义编码进入长时记忆），3-5 个关键词 + 串联关系 + 一句核心逻辑即可唤起整篇认知。
7. **防幻觉（source_summary）**：结构版 YAML 记录素材来源与核心内容摘要，叙事版生成必须基于它，避免 AI 编造案例。

## 命题检验（写前必做）

把感悟写成 PCD 之前，先检验这条道理本身是否成立。命题若本身有误，结构再完整也只是错误沉淀。检验四问：

1. **逻辑自洽**：推理链有没有断裂、偷换概念、以偏概全？
2. **反例检验**：主动找反例。存在反例不必然推翻命题，但要判断它是"推翻"还是"需加限定"。
3. **隐含假设**：命题依赖什么前提？（如反思能力、成本可承受、特定人群或处境）
4. **定性结论**：命题成立吗？是"普适真理"还是"相对优先级判断"？需要附加什么限定条件？

检验结论落实方式：限定条件写入**边界约束**，或写入**版本变更日志**。检验不通过的命题，不直接写文档，先与用户讨论修正。

**为什么必须有这一环**：PCD 沉淀的是"个人认知/原则"，会被未来的自己当作行动依据；如果命题本身是错的或适用范围被高估，记录得再工整也只是错误沉淀。检验的目的不是给道理泼冷水，而是明确"这条道理在什么前提下、什么范围内成立"。

**写后检验闭环**：命题检验是"写前"环节，但认知真正的检验发生在"写之后"——现实打脸的时刻。约定：当一条认知在现实中被验证或被推翻时，把事实记入**版本变更日志**（写清发生了什么、验证了什么），并同步更新 `status`。验证通过 → `status` 为「已验证」；被推翻 → 修正认知后为「已更新」，不再成立则标「已废止」；触及命题本身时重跑命题检验。这样检验从"写前一步"扩展成"写前 + 写后"的完整闭环。

## 认知状态（status）

YAML 中的 `status` 字段标注这条认知的验证状态，防止把未经验证的认知当结论用，形成认知生命周期管理：

- **假设**：新写初稿，完成命题检验但未经现实验证。
- **已验证**：在现实中被实际验证过，且验证记录已写入版本日志。
- **已更新**：曾被验证或使用，后因新认知/新证据被修正，仍成立但表述或范围已变。
- **已废止**：经现实检验不再成立，已从个人认知体系中退役（内容保留在文档中供回溯）。

`status` 与版本号联动：每次状态变化都必须同步更新 `updated` 并在版本日志记录原因。

## 连接规则（认知网络构建）

- **同域必连**：同一认知域（成长/学习/情绪/职业规划/决策）的 PCD 必须互相关联；
- **跨域有连接点可连**：不同认知域但内容上存在真实相关性时，可以考虑连接——学科之间本就互相渗透（数学与物理联系紧密）；先判断领域归属，再找内容相关性；
- **无连接点不连（宁缺毋滥）**：毫不相干的内容不硬连，避免"为连而连"；
- **连接点五类**：概念共用 / 机制互释 / 场景重叠 / 结论互用 / 约束互补——挂链接必须写明属于哪类连接点。

## 双层表达（骨架 + 血肉）

PCD 有两类读者：**AI 与检索工具**（需要结构化：要点、状态、标签、版本、关联），以及**当下的自己与他人**（需要可读性：连贯叙述、具体例子、推导过程）。双版本把两类需求物理分离，不再挤在一份文档里：

- **结构版（骨架层）**：YAML 元信息、要点化条目、状态、标签、关联。保证可检索、可核对、可迭代。
- **叙事版（血肉层）**：连贯段落、具体例子、推导过程、核心记忆卡。保证可读、可分享、能通读、能记住。

**验收标准**：叙事版整篇能像文章一样从头通读到尾，读者凭核心记忆卡能复述整篇论述。需要分享某条认知时，直接分享叙事版。

## 标准化结构（一份完整结构版 PCD 必须包含全部模块）

1. **YAML 元信息头部**：文档类型、标题、认知域（type）、核心金句、版本、认知状态（status：假设/已验证/已更新/已废止）、创建/更新时间、标签、素材来源（source）、素材摘要（source_summary）、`related_principles` 关联文档。用于知识库识别管理。
2. **思考缘起【背景】**：客观现象、现实矛盾、社会观察的出发点；避免私人隐私、情绪化叙事，从普遍现象切入。
3. **核心概念释义**：逐条解释自定义名词、关键概念，消除歧义。
4. **核心判断（主原则）**：最核心的观点与判断逻辑。
5. **边界与反例**：不适用场景、典型反例、常见误解、价值区分（认知层面 / 现实损失层面），防止道理泛化滥用。
6. **推导依据**：有序分步还原推理路径：客观现象 → 发现矛盾点 → 逐层推演 → 得到最终核心命题。隔很久重读也能看懂结论如何得出。
7. **行动指引**：把认知转化为具体可执行的行为建议。
8. **待持续观察/迭代点**：尚存不确定性、需持续跟踪的因素，为 status 流转提供依据。
9. **版本变更日志**：每一次修改新增一条记录，写明版本、日期、改动内容、改动原因。
10. **关联思考补充**：文字说明当前命题与 `related_principles` 关联文档之间的逻辑关系（互为补充、互为约束、递进推导）及连接点类型；无关联填「无」。

## related_principles 用法

- `related_principles` 填写 Obsidian 内部链接格式 `[[文档名]]`；没有关联就留空数组。
- 第 10 章「关联思考补充」写文字说明，例如："本文档和《接纳人性之中不完美》互为补充；前者讨论认知成长，后者讨论对自我的态度。（连接点：概念共用）"。

### YAML 头部参考案例

```yaml
---
document_type: PCD
title: 人是应该选择去一线城市发展，还是选择去老家发展
type: 职业规划
core_quote: "不要只比工资数字，要比工资背后的定价锚、产业密度和选择权。"
version: v1.0
status: 假设
created: 2026-10-31
updated: 2026-10-31
tags: ["#职业规划", "#决策", "#PCD"]
source: 抖音视频《同样的工作 一线三万五老家一万你会选哪个》
source_summary: 视频对比一线与老家的职业选择：定价锚决定薪资基线、产业密度决定隐藏收入、选择权决定未来上限；建议不到万不得已不主动收窄选择。
related_principles:
  - "[[成长的本质：理智脑驱动本能，而非对抗本能]]"
---
```

## 版本规则

- 首版：`v1.0`
- 小改（措辞、补充例子）：`+0.0.1`，如 v1.0.1
- 认知更新、结构调整：`+0.1.0`，如 v1.1.0
- 推翻重写：`+1.0.0`，如 v2.0.0
- 每次修改：更新 YAML 的 `version`、`updated` 与 `status`（若认知状态变化），并在版本日志新增一条记录；不删除旧想法，保留思想演变痕迹。
- 认知更新触及命题本身时，先重跑命题检验再定稿。
- 现实验证/推翻认知时：把事实记入版本日志（写后检验闭环），并同步更新 `status`。
- 双版本联动：结构版更新 → 叙事版标「待同步」→ 同步 →「已同步」；叙事版不设独立版本号。

## 使用场景

当你产生对成长、人性、处世的深度思考，脑子里只有零散口语化想法；或看到一条值得沉淀的视频/文章/对话，希望把它变成一份严谨、可存档、以后还能修改迭代的思想文档（双版本），就使用 PCD 这套范式。

## 使用流程

1. 收集素材或碎片化想法；
2. **先检验命题**（逻辑自洽、反例、隐含假设、定性结论），确认道理成立、明确限定条件；
3. 复制结构版空白模板，逐项填充（含 source 与 source_summary）；
4. 生成叙事版（8 要素 + 核心记忆卡），人工校验可读性与记忆性；
5. 存入 Obsidian，依靠 `related_principles` 建立双向链接；
6. 后续认知更新：升级结构版 `version`，更新 `updated` 时间，在版本日志写明改动与原因，同步叙事版；现实验证/推翻认知时，把事实记入日志并同步 `status`（写后检验闭环）。

## 关键提醒

1. PCD 不写纯粹情绪宣泄、私人隐私故事；追求理性思辨，从客观现象做逻辑推演。
2. 它是个人整理工具，不是学术论文，不需要严格学术格式，但逻辑必须自洽。
3. 这是个人知识库内约定的规范，对外交流不要宣称这是行业通用标准。
4. **隐私底线**：Skill 本体（开源部分）绝不含用户私密信息（姓名/手机号/邮箱/密码/账号/token）；PCD 是用户私有数据，写入用户真实经历前先询问确认。
